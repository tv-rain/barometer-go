# Changelog

All notable changes to Barometer Go will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/). A repository release version does not by itself establish implementation conformance, mobile-platform support, field validation, or support for a Draft Barometer specification.

### Added

- Egress Network Context acquisition, cache and clearing (DEV-647). When `Initialize` configures `network_context`, each attempt acquires egress context through its own path snapshot: a fresh entry of the new in-memory `networkcontext.Cache`, otherwise one request to the primary endpoint, otherwise one request to the optional fallback, otherwise `unavailable`. `execution.ContextFetch` makes the one HTTPS `GET` through a dialer of the attempt's path (the direct dialer, or CONNECT on the attempt's own proxy generation) with only `Host` and `Accept: application/json`, follows no redirect and accepts only a `200` uncompressed JSON body of at most 4,096 bytes, decoded strictly; each operation is bounded to 5,000 ms on the engine clock and acquisition ends with the attempt's deadline, cancellation or network change. Lookup bytes are not counted toward attempt budgets. Classifications must match trusted reviewed approvals (classification versions, country and region codes), a new adapter input with the context trust roots. The cache is keyed by access-network generation, path and proxy generation, reuses an entry up to 300 seconds, is never persisted, drops proxy entries on `SetProxy` and `ClearProxy`, starts a new epoch for each initialized generation and is erased by `ClearMeasurementData`. `execution.ContextConditions` evaluates `required_fields` and `allowed_country_codes` per attempt: a missing field is `network_context_unavailable`, a country outside the allowlist `constraints_unsatisfied`, and an unknown value never matches. Admission no longer rejects egress requirements as `task_unsupported` (REQ-TRUST-0036).
  - Test-only `internal/testkit/contextendpoint`: a synthetic CA, HTTPS endpoints on `127.0.0.1` with scripted responses and request capture, and a name-mapping dialer. No real endpoint is chosen or contacted; real endpoints need privacy-reviewed endpoints (REQ-CONTEXT-0032) and privacy and safety review before field use.
  - `TestAdmissionHasNoNetworkDependency` now permits `crypto/tls` in the root closure when `internal/execution` is its only module importer; the admission closure still links no network or TLS package.
  - The conformance families executed and still planned are recorded in `docs/execution-models.md`; the milestone traceability manifests are unchanged. No platform, field or conformance support is claimed, and egress classification is not evidence of censorship.

- Dynamic proxy replacement and clearing (DEV-646, public-API review point): `Client.SetProxy(string) error` validates the complete standalone proxy object before cancellation and returns the approved code-only `proxy_rejected` on invalid input. `Client.ClearProxy() error` removes the proxy after cleanup. Both serialize with lifecycle and policy replacement, seal the old proxy generation against new reservations, cancel its runs with `proxy_reconfigured` and wait for one bounded cleanup budget before atomic activation. Direct runs continue. Cleanup failure installs nothing and blocks the client for recovery clearing or close. Reservations retain one snapshot through path planning, execution and output; old runs cannot retry on the new endpoint or direct path. Policy replacement preserves the dynamic proxy, and endpoint/generation values stay out of results, bundles and persistence. Synthetic lifecycle, race and two-proxy loopback tests are added. Egress cache invalidation (DEV-647), NET-05 whole-profile evidence and production codecs/rules (DEV-454), native binding and host review (DEV-455) remain pending; no runtime, mobile or field support is claimed.

- Proxy tasks run through the HTTP CONNECT path (DEV-645). A task with `network_path: proxy` runs through the single local HTTP/1.1 CONNECT proxy configured at `Initialize` and never falls back to the direct path. `execution.ProxyDialers` gives each attempt a dialer bound to the generation's proxy snapshot; every stream opens its own tunnel to the loopback endpoint with a bounded `CONNECT` for the exact authority (an IP address and port, or a normalized hostname resolved behind the proxy) carrying only `Host`, and accepts only a valid `HTTP/1.1 2xx` head within 8,192 bytes, a new reviewed implementation input. The attempt scope wraps the dialer, so each tunnel counts toward `max_connections` and the `CONNECT` exchange is not metered (REQ-LIMIT-0033, GO-SPEC-ISSUE-005). A failed endpoint connection is `incomplete` with `proxy_unavailable`, and a refused, closed, malformed, oversized or deadline-cut `CONNECT` is `proxy_connect_failed`; the failure is the attempt's cancellation cause, so an outcome a runner builds from the failed dial is not retained. The engine applies the plan's new `PathCheck` before each proxy attempt: a missing proxy, a path authority that does not permit it or an incompatible test records `not_run` with `proxy_not_configured`, `proxy_not_permitted` or `proxy_path_unsupported` and makes no contact (GO-SPEC-ISSUE-009); a proxy task without a configured proxy is therefore started rather than refused with `run_not_due`. `execution.NetworkSatisfiable` accepts the proxy path. `networkcontext.Direct` becomes `networkcontext.Source` with `NewDirect` and `NewProxy`; proxied results record egress `{status: unavailable, lookup_source: none, network_path: proxy, connection_code}` and never the proxy host, port, generation or `CONNECT` exchange. The root package's `directPath` becomes `networkPaths`, `admission.Admitted` gains `Paths`, and the dependency rule is renamed "only the network path dialers open sockets". `CC-EXECUTION-ENVELOPE`, `CC-PROXY-HTTP-CONNECT-BEHAVIOR`, `CC-PROXY-TASK-SELECTION`, `CC-PROXY-RESULT-METADATA` and `CC-PROXY-PROXY-CONFIGURATION` run with synthetic runners against the new test-only scripted proxy (`loopback.ListenProxy`); `CC-EXECUTION-FIELDS-NETWORK-PATH` and `CC-PROXY-OVERVIEW` run all rows but their NET-05 and DNS-01 rows and stay planned (DEV-454). The manifests are unchanged until the next milestone update. Proxy replacement, clearing and `proxy_reconfigured` remain DEV-646, proxied egress lookup DEV-647, production runners and rules DEV-454 and native wiring DEV-455; no runtime, platform or field support is claimed, and a proxied outcome is not evidence of censorship.
