# Changelog

All notable changes to Barometer Go will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/). A repository release version does not by itself establish implementation conformance, mobile-platform support, field validation, or support for a Draft Barometer specification.

- Replay, redelivery, conflict, rollback and expiry handling with atomic replay persistence at admission (DEV-591). `Admitter.Admit` runs `Gate` and then steps 10 and 11 under the instance's admission serialization:

- Target registration matching at admission (DEV-588). - Admission gates for steps 1 to 6 (DEV-586). `admission.Admitter.Gate` resolves the delivery record, requires authenticated remote or reviewed embedded origin, reads trusted time, rejects remote `issued_at` more than 300 seconds ahead and tasks over 65,536 bytes before parsing, then validates the top-level schema and exact version, `task_id` and every common field, registered limit and expiry, and decodes input and options through the registry-selected codec. It returns only the code-only class of the first failing step (REQ-TRUST-0037), including `task_unsupported` for an unregistered test version or unrecognized risk factor type, and holds no transport, persists nothing and publishes no handle. To apply the public step order, `taskdecode` adds staged `Envelope`, `Fields` and `Parameters` decoding, `jsondecode` adds an `Any` kind, `Validate` and limit-marked schemas whose errors also match `ErrLimit`, and `validation` adds `TaskID` and the refining classes `ErrLimit`, `ErrExpired` and `ErrUnsupported`; existing error classes still match. Shape is now validated before version selection, and delivery records bind up to 131,072 bytes so oversized tasks reach the byte-limit check. The cross-cutting manifest and unit-test evidence are rebaselined to Go `b25f107`, with the DEV-597 mapping preserved as historical; 14 requirements become `partial`. Issuer, target, risk, replay and acceptance steps, facade wiring and the planned family cases remain; no runtime, platform or field support is claimed.

- Internal delivery-record seam for admission (DEV-585), creating `internal/admission`. `admission.DeliveryStore` is an instance-owned store with bounded capacity and lifetime. It installs embedded-origin records, and remote records only through a `RemoteVerifier`, binding exact task bytes to trusted source context through `task.DeliveryRecord`. It resolves records by an opaque random reference and rejects missing, malformed, forged, foreign-instance, expired, stale-generation and byte-mismatched records as `task_source_unauthenticated`, and unavailable trusted time as `task_trust_unavailable`. Invalidation hooks cover data clearing, policy replacement and close. The only remote verifier is the synthetic one in the test-only `internal/testkit/delivery`. The dependency check now restricts admission imports and forbids measurement packages from importing admission. No production remote authentication, facade wiring, admission pipeline, requirement status change or support claim.

- Internal registered-test registry for admission (DEV-584). `internal/registry` maps an exact `(test_id, test_version)` to its task codec, registered baseline risk, a proxy-compatibility rule and NET-05 composite or step eligibility. It is immutable after construction, bounded to 256 entries and safe for concurrent reads. Lookup has no version fallback or partial match, and construction rejects incomplete, duplicate or codec-inconsistent entries atomically. The dependency check now restricts registry imports and forbids measurement packages from importing it; the architecture now states that validation cannot import the registry. Only test-scoped synthetic entries exist. No production entry, runner composition, admission behavior, requirement status or support claim is added.
