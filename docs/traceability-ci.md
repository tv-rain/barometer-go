# Traceability CI Checks

DEV-475 adds the `Traceability and conformance smoke` job to the existing CI workflow. It checks working-tree manifests and requirement-reference comments, runs the public checker's synthetic positive/negative suite and the Go conformance fixture smoke tests, and retains full JSON metadata reports as a CI artifact for 14 days. Compilation and synthetic cases establish no runtime, platform or field support.

## Reproduce Locally

Use Go 1.26.0 or later, Git, tar, and Python 3.10 or later with the public tooling's pinned packages. CI uses Python 3.14. Supply an explicit public specification checkout with full history containing commits `f889a381c84a781176024f3fed3a3d4f5c92b241`, `e6257ec64564ad415a2d6c1f8d106fa1763d7de8`, `12062471875bbfbc55eafc94dc5a7ea4cd07ca5e`, `bb805f07a36630db7250d5ab63006ed5e351f7a7`, `4743b636f29feb1f0f8d042866d04ccda3532938`, `e97502747c917a16bc2b71337535ff972bbd7d64`, `d93aff93cbc17e7c065fb40d8f6e2e01a697bf35`, `5a37e82865a08922c4821c7318656286933421e5` and `a944ed6c389fec9f0d089f0044ead6fe845328b1`; no private repository is required. The script never fetches, installs packages or discovers sibling checkouts. Dependency installation is a separate network operation.

From this repository, with the public checkout at the explicitly selected example location:

```sh
python3 -m venv /tmp/barometer-traceability-venv
git -C ../barometer-spec show 5d01879cfd1d47396c780befa2567f7e90439948:scripts/requirements.txt > /tmp/barometer-traceability-requirements.txt
/tmp/barometer-traceability-venv/bin/python -m pip install -r /tmp/barometer-traceability-requirements.txt
make traceability PYTHON=/tmp/barometer-traceability-venv/bin/python SPEC_CHECKOUT=../barometer-spec REPORT_DIR=/tmp/barometer-traceability-reports
make check
```

The pinned dependency file is the public tooling's `scripts/requirements.txt` at the tooling commit above; CI installs the same file. Use a Go 1.26 toolchain first on `PATH`; the public checker tests build their helper with `GOTOOLCHAIN=local`, so an older default `go` that would otherwise switch toolchains fails. If `go version` outside this module reports an older release, prepend a Go 1.26.0+ `bin` directory to `PATH` for the command, for example `PATH="$(go env GOROOT)/bin:$PATH"` run from inside this module where automatic selection has already chosen Go 1.26. Before any checkout export or test, the driver checks that the `go` first on `PATH` (with `GOTOOLCHAIN=local`) meets the `go.mod` directive, that the selected Python is 3.10 or later, and that it can import `jsonschema`. It reports every missing prerequisite and exits with status 2; `scripts/test_traceability_ci.py` covers these failure paths. Both checkouts need the selected immutable commits, including Go inventory commit `c06ce6b7b73b8520f35ce10982315fcb4d05615b` and the manifests' implementation baselines. Reports must be outside both checkouts. The driver independently exports the checker/tooling snapshot and the current reference-source snapshot from their pinned Git commits into temporary storage. Only the tooling snapshot supplies executable checker code and schema; the reference snapshot supplies current documents and catalog. The driver builds the standard-library declaration helper there, and removes that storage on exit. Working-tree changes to the supplied public checkout cannot select executable tooling or schema. Python packages are development dependencies, with no Go module dependency or change to `make check` prerequisites.

## Checks and Failure Rules

- Validate current public catalog integrity and Go working-tree `.md`/`.go` requirement-reference comments against the reference-source pin, including allocation/retirement history from the tooling baseline.
- Require every Go working-tree `// requirement-ref` ID to be active in the current reference catalog. Unknown or retired IDs always fail. Missing mappings for requirements already allocated in the immutable milestone catalogs fail; an active requirement allocated only after those catalogs receives an explicit pending-milestone mapping warning under coordination decision 0012. Missing source/test location links also warn until the milestone update. The independent inventory check still rejects removal of older mappings; warnings do not invent a mapping, transfer predecessor evidence or establish conformance. Without milestone catalog metadata the reference check fails closed on an unmapped ID. `requirement-history` citations and Markdown plans are excluded from Go source-location consistency checks.
- Run the public tooling tests, including broken references, false implementation/support claims, stale baselines, malformed metadata and the public invalid scenarios, using synthetic local Git repositories.
- Validate each working-tree manifest with the canonical public checker and independently selected specification/implementation commits. Existing paths, selectors, issue/evidence references and support gates are checked against those immutable objects.
- Compare each manifest's allocated IDs with its original mapping at the independent Go inventory commit. Removal of an allocated ID or its target/case mapping fails, even though partial-mode metadata alone permits omissions. The only exception is an ID that the public catalog marks retired at the manifest's pinned specification baseline. It may leave the current manifest only when every declared successor keeps a target and case mapping.
- Reject vague case plans in the current manifests (DEV-572): an automated plan led, in any sentence or coordinated clause, by Review, Inspect or Plan; an automated plan shorter than 100 characters after its family-class prefix; plan text shared by two cases; a plan naming a requirement ID it is not mapped to; and an `RV-` review case without its fixed opening, reviewer role, reviewed artifact, checklist, evidence record and own Markdown heading. `UT.*` cases are exempt from the wording rules. The driver prints automated, review and unit-test case counts separately; review cases are not automated coverage. See [typed review cases](traceability-manifest.md#typed-review-cases).
- Require the JSON files under `traceability/` to be exactly the current manifests. Earlier manifests are retained at the commits where they were current and are not committed as copies or re-checked.
- Run `go test -count=1 ./internal/testkit/conformance` against the current checkout. The ordinary Go CI job continues to run `make check` independently.

The driver exits nonzero for any failing command, invalid manifest, inventory loss or setup error. It writes complete checker reports, including every permitted gap and review assertion, and prints finding counts plus individual errors. CI uploads reports even when validation fails. No report is substituted for execution of a mapped case.

## Baselines and Evidence Limits

Current reference-source scanning is independently pinned to public Draft `0.1.0` revision `f889a381c84a781176024f3fed3a3d4f5c92b241`, the merged NET-03 response classification and outcome selection (public PR #35, REQ-NET-03-0041 to REQ-NET-03-0043), which includes the earlier HTTP-01 terminal-response precedence rule, step-8 input/options admission class and explicit-IP-only CONNECT contract. The CI checkout uses this same revision, guarded by a cross-file regression test. REQ-NET-03-0041 to REQ-NET-03-0043 are active there and absent from the milestone catalogs; their mapping/location warnings remain visible until the next milestone update. Both manifests use the earlier revision `e6257ec64564ad415a2d6c1f8d106fa1763d7de8` as their milestone baseline, so REQ-PROXY-0043 through REQ-PROXY-0046, REQ-CONTEXT-0043, REQ-HTTP-01-0051, REQ-HTTP-01-0052, REQ-TRUST-0056 and REQ-OPTIONS-0033 are mapped, and REQ-OPTIONS-0019, REQ-PROXY-0019, REQ-PROXY-0023, REQ-PROXY-0026, REQ-PROXY-0042 and REQ-CONTEXT-0020 are retired there. Retired predecessors cannot be used as current references. Tooling and historical manifest/evidence baselines remain independent and unchanged; no older conformance claim is promoted to a successor.

Public tooling/schema are pinned to `5d01879cfd1d47396c780befa2567f7e90439948` (DEV-562); the tooling, schema and dependency file are unchanged from the earlier pins `84f52f8872a5af9e6d97894611e3b2eaba18aba8`, `4743b636f29feb1f0f8d042866d04ccda3532938`, `e97502747c917a16bc2b71337535ff972bbd7d64`, `d93aff93cbc17e7c065fb40d8f6e2e01a697bf35`, `5a37e82865a08922c4821c7318656286933421e5` and `a944ed6c389fec9f0d089f0044ead6fe845328b1`, and the newer catalogs add REQ-SAFETY-0031 and REQ-SCHEDULE-0043 (`5a37e82`), REQ-TRUST-0036 to REQ-TRUST-0038 (`d93aff9`), and REQ-TRUST-0039, REQ-PROXY-0042, REQ-TRUST-0040 to REQ-TRUST-0054 and REQ-LIMIT-0032 while retiring nine earlier REQ-TRUST IDs (`e975027`), REQ-TRUST-0055 (`4743b63`), and REQ-RESULT-0051 to REQ-RESULT-0053, REQ-EXECUTION-0031 and REQ-NET-05-0061 while retiring REQ-RESULT-0024 and REQ-EXECUTION-0015 (`84f52f8`), and REQ-LIMIT-0033, REQ-LIMIT-0034 and REQ-EXECUTION-0032 while retiring REQ-LIMIT-0003 and REQ-EXECUTION-0014 (`5d01879`). Both manifests use public baseline `e6257ec64564ad415a2d6c1f8d106fa1763d7de8` and Go baseline `dbf43f6fd2d27e85c6f920a4a864991f59733bbf`, the DEV-622 strict-JSON update after the DEV-670 milestone that closes Measurement web reachability and composite (DEV-657), as the [cross-cutting plan](cross-cutting-requirements.md) and [measurement plan](measurement-requirements.md#status-authority-and-baselines) record. Each manifest's linked `UT.*` unit-test cases passed at its Go baseline; the evidence records are in a later commit, as the [manifest guidance](traceability-manifest.md#manifest-preparation-and-maintenance) permits. Earlier manifests are retained at the commits where they were current rather than as committed copies, and the driver does not re-check them (coordination decision 0012).

Planned targets/cases and declared unallocated sources remain permitted, visible gaps. A `partial` requirement with a passing `UT.*` case keeps its missing-conformance gap while any mapped planned family is unexecuted. The CI job does not re-execute the evidence cases at their baseline; the ordinary CI job runs the current tests. The inventory gate prevents loss of previously allocated mappings; it does not infer untagged obligations or require unfinished implementation to pass. Changes to case meaning, semantic completeness, inventory completeness, evidence authenticity and issue closure/adoption still require human review. Adding an ID or preserving a nonempty case list cannot prove coverage. Future source allocations require reviewed pin/inventory updates; this job does not track a moving public branch.

Reports are not committed; earlier committed reports remain in git history. CI outputs include a provenance record with tooling, current reference source, immutable manifest baselines, inventory and consumer revisions. During local development, the consumer revision names HEAD while manifests, reference comments and synthetic tests include uncommitted changes; such a run is local validation, not immutable committed evidence. No measurement, public API, native adapter, release or support status is changed by this task.
