# Changelog

All notable changes to Barometer Go will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/). A repository release version does not by itself establish implementation conformance, mobile-platform support, field validation, or support for a Draft Barometer specification.

## [Unreleased]

### Changed

Registry proxy compatibility stays unimplemented at admission pending public disposition. Records only; no code, traceability, requirement status or support change.

- Adopted the GO-SPEC-ISSUE-008 disposition (DEV-597). `task.AdmissionError` gains the `task_unsupported` code (REQ-TRUST-0036). The admission design and the admission-related case plans now name the REQ-TRUST-0037 class for every condition previously left *open*, make first-failing-step precedence normative and fail closed on unavailable replay state for embedded tasks (REQ-TRUST-0038). The cross-cutting traceability manifest, CI tooling pin and unit-test evidence are rebaselined to public `d93aff9` and Go `c49a77f`, with the DEV-583 mapping preserved as historical. REQ-TRUST-0036 is `partial` and REQ-TRUST-0037 and REQ-TRUST-0038 are `planned`. GO-SPEC-ISSUE-008 stays open until the admission tasks provide runtime evidence. No admission implementation returns the new code yet, and no runtime, platform or field support is claimed.

- Recorded the admission design (DEV-583) in `docs/admission.md`: ordered admission steps and error classes, consumed capabilities and owners, atomic replay persistence, execution outputs and package-creation checklists for `internal/admission` and `internal/registry`. Opened GO-SPEC-ISSUE-008 for admission error classes the public text does not assign, including rejection of unsupported features. Rewrote 17 thin admission-related cross-cutting case plans as measurable plans with `Requirements:` lists, preserving the DEV-582 manifest as historical. Documentation and traceability only; no package, behavior, requirement status or support change.

- Adopted the GO-SPEC-ISSUE-007 disposition (DEV-582). Task validation now rejects a missing or empty `risk_factors` list for `medium`, `high` and `unknown` risk (REQ-SAFETY-0031). The existing `local`-only time-window `timezone` rule is unchanged and now evidenced (REQ-SCHEDULE-0043). Validation, decoding and conformance-fixture cases are added, and the cross-cutting traceability manifest, CI tooling pin and unit-test evidence are rebaselined to public `5a37e82` and Go `4575079`, with the DEV-572 mapping preserved as historical. The six affected requirements are `partial`, not `implemented`. GO-SPEC-ISSUE-007 stays open for admission, binding and host evidence. Producers that send `risk_factors: []` for non-`low` risk are now rejected; no runtime, platform or field support is claimed.

- Recorded Foundation acceptance (DEV-450) in the README and the Foundation validation boundary. Documentation only; no code, traceability, runtime or support status changes.

- Made every traceability case plan measurable or explicitly a human review case (DEV-572): templated measurement termination, minimization, version, interpretation and safety plans are replaced with per-measurement specifics; thin cross-cutting plans gain inputs, boundary values, expected outcomes and requirement IDs; judgement-based remainders become 48 typed `RV-*` review cases that are not automated coverage; and the CI traceability driver rejects vague, shared or untyped plans, with negative tests. Baselines, requirement statuses and allocations are unchanged, the DEV-569 manifests are preserved as historical, and no case is executed and no support claimed.

- Reconciled the GO-SPEC-ISSUE-002 disposition with its current state: the public vocabulary resolution merged at public `a944ed6`, while the finding stays open pending runtime and applicable binding/host adoption evidence. Documentation only; no runtime, traceability or support status changes.

- Linked existing Foundation code and unit tests as partial traceability evidence at Go baseline `c5f4e92`: 129 IDs cited by reviewed `requirement-ref` comments are `partial` with existing locations and passing `UT.*` unit-test cases backed by a committed evidence report, 12 comments that did not demonstrate their requirement were removed, prior manifests are preserved as historical, and CI now fails on unknown, retired, unmapped or unlinked Go references. Planned family cases stay unexecuted; no implemented requirement, runtime, platform or field support is claimed.

- Rebaselined the cross-cutting traceability mapping to public specification `a944ed6`: successors of retired REQ-OBS-0011/0021 and new observation-vocabulary requirements are mapped to planned case families, the prior mapping is preserved as a byte-identical historical manifest, and the CI inventory gate permits removal only of catalog-retired IDs whose successors are mapped. No implementation, conformance, historical report or support status changes.

### Added

- Admission evidence closeout (DEV-594): tests only, no behavior change.
  - `FuzzAdmitTask` drives `Client.AdmitTask` with arbitrary task text and fuzzed sources (exact and mismatched embedded records, remote deliveries with fuzzed authentication and issuance time, forged and foreign-instance references). Every call either admits with one handle and one replay record, or returns one fixed public admission class and leaves no handle, replay record or run. `FuzzGate` gains hostile seeds.
  - Strict JSON at the admission boundary, the admission share of GO-SPEC-ISSUE-001: escaped-equivalent and nested duplicate names, escaped unknown names, non-exact integer spellings, exact versions after decoding escapes, framing, invalid UTF-8, nesting depth and escaped complete-input bytes are rejected atomically at the gate and through the facade for both reviewed origins.
  - `TestAdmitTaskHostileSources` covers forged, foreign-instance, mismatched, unauthenticated, integrity-failing, future-issued and expired sources, and `TestCcTrustAcceptedTaskOrigins` executes the `CC-TRUST-ACCEPTED-TASK-ORIGINS` family.
  - `TestAdmissionHasNoNetworkDependency` requires the transitive dependency closure of the root package and of `internal/admission` to contain no network, TLS, process-execution or plugin package. It replaces, in the root admission tests, a recording transport that was never connected to the client. This is structural evidence for the host build, not observed runtime behavior.

  The admission design records the fuzz runs and why each other admission case family stays planned. No runtime, platform or field support is claimed.

- Local policy activation and replacement by reinitialization (DEV-593), through an unexported root-package seam with no production caller; no identifier is exported and no policy format is added.
  - `Initialize` keeps the adapter-installed policy and its target registrations immutable for the generation and fails closed with `not_initialized` for a policy generation below the highest this instance has activated, including after clearing.
  - `replacePolicy` first validates while the current generation stays active: the policy must be complete and valid, strictly above the active generation and not below the highest generation of retained replay records, and the successor generation must build. A refusal returns the seam-only code `policy_rejected` and leaves the previous policy, its handles and its delivery references active.
  - It then quiesces: it cancels the generation's adapter context, invalidates task and run handles, drops delivery records and moves the delivery store to the new generation, waits for reserved entry points and activates the prepared generation. A task no longer permitted is rejected when redelivered, and a delivery under the earlier generation is `policy_rollback`.
  - A failure after validation leaves the client uninitialized with no policy (`not_initialized`), or blocked with `cleanup_incomplete` while reserved work continues; it never activates part of the new policy or an earlier generation.

  The cross-cutting traceability manifest is rebaselined to Go `954b7d7` with the DEV-592 mapping preserved as historical. `CC-TRUST-LOCAL-POLICY-LIFECYCLE` is reworded to the implemented steps and executed, its rows that need components that do not exist yet move to the planned `CC-TRUST-LOCAL-POLICY-LIFECYCLE-RUNTIME` case, and REQ-TRUST-0029 to REQ-TRUST-0032 become `partial`. Persisting a generation floor across restart or clearing stays out of scope (rollback below retained replay records is still detected). No production adapter, policy authentication, run cancellation, Network Context cache, runtime or platform support is included.

- `Client.AdmitTask` (DEV-592), the public-API review point for the documented `AdmitTask(taskJSON, sourceRef string) (string, error)` signature; no other identifier is added.
  - It reserves the current generation, runs every admission step through `Admitter.Admit` and publishes a task handle only after the replay record is durable. A rejection returns the code-only public admission class and leaves no handle; calls outside the initialized state return the API-local lifecycle codes.
  - An exact redelivery, through the same or a new delivery reference, returns the same handle in the current generation without a new replay record, a run or a later expiry. Concurrent identical deliveries share one handle. After reinitialization a redelivery resolves to the retained acceptance under a new handle.
  - Admission adapter calls run under a per-generation context bounded by the lifecycle deadline; `Close` and clearing cancel it. A panic below the facade returns `task_trust_unavailable` with no handle.
  - A full task table first reclaims tasks whose validity has ended; it never evicts a valid task and otherwise returns `capacity_exceeded`. The facade adds no byte check, so the REQ-TRUST-0037 step order, including the complete-task byte limit after delivery resolution, stays the admitter's.

  The cross-cutting traceability manifest is rebaselined to Go `7b098a6` with the DEV-600 mapping preserved as historical; four `UT.root.*` cases add facade-level aspects to REQ-TRUST-0017, REQ-TRUST-0024, REQ-TRUST-0035, REQ-TRUST-0037 and REQ-TRUST-0038, which stay `partial`, and the admission families stay planned. Execution, runs, proxy compatibility at admission, policy replacement (DEV-593), production adapters and native wiring (DEV-455) are not included. No runtime, platform or field support is claimed.

- The root `Client` lifecycle shell (DEV-600), the public-API review point for `NewClient`, `Initialize`, `Close` and `ClearMeasurementData` with the documented signatures; no other identifier is exported, and `TestPublicSurfaceMatchesDocumentedSignatures` enforces this.
  - Lifecycle states follow the documented table. Lifecycle calls do adapter work without holding the lock and refuse concurrent transitions with `transition_in_progress`. An unexported reservation counter lets future admission, run and bundle entry points serialize with transitions.
  - `Initialize` binds trusted adapters through an unexported seam with no production caller, so it fails closed with `not_initialized`. It decodes only the closed configuration container through `internal/config`; an invalid local policy is left to fail admission as `task_policy_unavailable`.
  - Bounded task and run handle tables, scoped per instance and generation, hold opaque 128-bit random handles distinct from `task_id`, `run_id` and `bundle_id`. They return `capacity_exceeded` and `handle_unavailable` and are redacted from formatted output.
  - `Close` invalidates handles and delivery records and releases runtime state without deleting replay or pending state. `ClearMeasurementData` blocks work and invalidates handles and delivery references; until persistent clearing exists (DEV-564, DEV-577) it returns `clearing_incomplete` and keeps activity blocked.
  - Errors carry one fixed API-local code with no wrapped cause, and every exported method recovers panics to a fixed code.

  Reviewed implementation inputs: 256 task handles, 256 run handles and a lifecycle deadline of 5 seconds by default, at most 30 seconds. The cross-cutting traceability manifest is rebaselined to Go `73faaf5` with the DEV-591 mapping preserved as historical; four `UT.root.*` cases make REQ-LINKAGE-0023 and REQ-LINKAGE-0024 `partial`, and `CC-LINKAGE-CLEAR-DATA-CONTRACT` stays planned. No admission, execution, bundle, proxy, policy-replacement, persistent-clearing, runtime or platform support is claimed.

- Replay, redelivery, conflict, rollback and expiry handling with atomic replay persistence at admission (DEV-591). `Admitter.Admit` runs `Gate` and then steps 10 and 11 under the instance's admission serialization:
  - the same replay key and digest is an idempotent redelivery that writes nothing and keeps the original expiry;
  - a different digest is `task_id_conflict`;
  - unavailable, corrupt, invalid or full replay state is `task_trust_unavailable` for remote and embedded tasks (REQ-TRUST-0038);
  - a new key is admitted only after one atomic, conditional commit of its replay record.

  The new `internal/persistence` package defines the `ReplayStore` contract and the `ReplayRecord`. The record holds the replay key, the exact-byte digest, the accepted policy generation, the origin, the expiry and the retention end: validity plus 86,400 seconds, capped at 691,200 seconds. The test-only `internal/testkit/replay` package provides a fault-injectable store. `NewAdmitter` now requires a replay store.

  Recorded decisions:
  - rollback across a restart is detected from the highest generation among retained replay records rather than a separate durable floor, with the documented limitation after clearing or retention lapse;
  - admitted-task records are deferred to DEV-576 and DEV-577.

  The cross-cutting manifest and evidence are rebaselined to Go `9283870`, with the DEV-590 mapping preserved as historical. `CC-TRUST-REPLAY-DUPLICATE-AND-ROLLBACK-HANDLING` is the first executed conformance family case; its post-clearing rows move to the planned `CC-TRUST-REPLAY-AFTER-CLEARING` case (DEV-564). REQ-TRUST-0021 to REQ-TRUST-0024, REQ-TRUST-0038 and REQ-LIMIT-0023 become `partial`.

  Clearing (DEV-564), production and platform storage (DEV-577, DEV-455), handle publication and facade wiring (DEV-592) are not included. No runtime, platform or field support is claimed.

- Rejection of tasks that require unsupported capabilities at admission (DEV-590). `Gate` now returns `task_unsupported` (REQ-TRUST-0036) at step 6 for a valid task whose `execution.network.context` has a non-empty `required_fields` or an `allowed_country_codes` list, because this build does not acquire egress Network Context (DEV-578). It also returns `task_unsupported` at step 8, after input and options, for a registered NET-05 composite enabled by both issuer and deployment, because composite steps cannot be matched against registrations yet (DEV-454). Unregistered NET-05 stays `task_unsupported` at step 4, and NET-05 without composite enablement stays `task_issuer_not_authorized` at step 7. A context with neither member states no requirement and is admitted. Rejection is atomic and performs no context lookup, endpoint call or other network activity. Each check is removed by the task that delivers its capability. The cross-cutting manifest and unit-test evidence are rebaselined to Go `295dea9`, with the DEV-589 mapping preserved as historical. Three new unit-test cases add aspects to REQ-TRUST-0018, REQ-TRUST-0036 and REQ-TRUST-0037, and `CC-CONTEXT-EXECUTION-INTEGRATION` gains an admission rejection row; no requirement changes status and the planned families stay `planned`. No runtime, platform or field support is claimed.

- Effective risk and the consent requirement at admission (DEV-589). Step 9 of `Gate` now computes effective risk as the most restrictive of the registered baseline, the task-declared level and the locally determined risk, which is the reviewed baseline of every target registration the task matched. `unknown` from any input dominates, and no input lowers the baseline. Effective risk is held to the intersected issuer and local maximum, medium-risk enablement and unknown-risk exception (`task_issuer_not_authorized`). An unreadable matched registration or an out-of-range level counts as `unknown`. Effective risk and the consent requirement (task, issuer or deployment) are carried on the gated value for acceptance. Consent validity is not checked at admission: the consent-status capability and its `StartRun` consumer are documented as handoffs to DEV-455 and DEV-576. No trusted local assessment resolves `unknown` factors (REQ-SAFETY-0019). The cross-cutting manifest and unit-test evidence are rebaselined to Go `41c6f06`, with the DEV-588 mapping preserved as historical. REQ-SAFETY-0004, REQ-SAFETY-0005, REQ-SAFETY-0010, REQ-SAFETY-0019 and REQ-SAFETY-0021 to REQ-SAFETY-0029 become `partial`, and REQ-SAFETY-0017, REQ-TRUST-0011 and REQ-TRUST-0037 gain aspects. The `CC-SAFETY-*` families stay `planned`, and no runtime, platform or field support is claimed.

- Target registration matching at admission (DEV-588). Registry entries now require a `registry.TargetRule` that reports, for the codec's normalized parameters, every destination or name the task would contact as a role and complete typed `task.TargetTuple`. A rule that reports false or no measurement target rejects the task. In step 8, after path authority, `Gate` requires every tuple to match a registration that meets all of these conditions: permitted by both issuer and local policy, for the exact test/version and role, with an exactly equal tuple, not expired at trusted time, and permitting the task's path. Redirect tuples must also be listed by a matched registration. Any failure is `target_not_registered`. Matching uses normalized typed values only, with no substring, suffix or wildcard rule, and the carried registration IDs narrow to the matched ones. The REQ-TRUST-0016 pre-contact check of resolved addresses and redirects is documented as an execution obligation for DEV-454 and DEV-578. The cross-cutting manifest and unit-test evidence are rebaselined to Go `cb67292`, with the DEV-587 mapping preserved as historical. REQ-TRUST-0013, REQ-TRUST-0014 and REQ-TRUST-0015 become `partial`, and REQ-TRUST-0011 and REQ-TRUST-0037 gain aspects. Proxy compatibility, composite steps, locally determined risk and consent, replay, acceptance and facade wiring remain. `CC-TRUST-TARGET-REGISTRATION` stays `planned`, and no runtime, platform or field support is claimed.

- Issuer authorization at admission (DEV-587). `admission.NewAdmitter` binds the active `task.LocalPolicy` snapshot. `Gate` now resolves the policy generation (`policy_rollback` for a lower source generation, `task_policy_unavailable` for a higher one or no policy), the issuer and the exact test version permitted by both issuer and deployment, then enforces the intersected numeric ceilings (`task_limit_exceeded`), label namespaces at a `.` boundary, network path and the issuer and local risk bounds on the registered and declared risk (`task_issuer_not_authorized`). No value is clamped and no permission is a union. The unpublished effective authority, with narrowed ceilings, registration IDs and consent requirement, is carried for later steps. The cross-cutting manifest and unit-test evidence are rebaselined to Go `aab88f5`, with the DEV-586 mapping preserved as historical; five requirements become `partial`. Target matching, proxy compatibility, locally determined risk and consent, replay, acceptance and facade wiring remain; the issuer-authorization and limit-handling families stay `planned`, and no runtime, platform or field support is claimed.

- Admission gates for steps 1 to 6 (DEV-586). `admission.Admitter.Gate` resolves the delivery record, requires authenticated remote or reviewed embedded origin, reads trusted time, rejects remote `issued_at` more than 300 seconds ahead and tasks over 65,536 bytes before parsing, then validates the top-level schema and exact version, `task_id` and every common field, registered limit and expiry, and decodes input and options through the registry-selected codec. It returns only the code-only class of the first failing step (REQ-TRUST-0037), including `task_unsupported` for an unregistered test version or unrecognized risk factor type, and holds no transport, persists nothing and publishes no handle. To apply the public step order, `taskdecode` adds staged `Envelope`, `Fields` and `Parameters` decoding, `jsondecode` adds an `Any` kind, `Validate` and limit-marked schemas whose errors also match `ErrLimit`, and `validation` adds `TaskID` and the refining classes `ErrLimit`, `ErrExpired` and `ErrUnsupported`; existing error classes still match. Shape is now validated before version selection, and delivery records bind up to 131,072 bytes so oversized tasks reach the byte-limit check. The cross-cutting manifest and unit-test evidence are rebaselined to Go `b25f107`, with the DEV-597 mapping preserved as historical; 14 requirements become `partial`. Issuer, target, risk, replay and acceptance steps, facade wiring and the planned family cases remain; no runtime, platform or field support is claimed.

- Internal delivery-record seam for admission (DEV-585), creating `internal/admission`. `admission.DeliveryStore` is an instance-owned store with bounded capacity and lifetime. It installs embedded-origin records, and remote records only through a `RemoteVerifier`, binding exact task bytes to trusted source context through `task.DeliveryRecord`. It resolves records by an opaque random reference and rejects missing, malformed, forged, foreign-instance, expired, stale-generation and byte-mismatched records as `task_source_unauthenticated`, and unavailable trusted time as `task_trust_unavailable`. Invalidation hooks cover data clearing, policy replacement and close. The only remote verifier is the synthetic one in the test-only `internal/testkit/delivery`. The dependency check now restricts admission imports and forbids measurement packages from importing admission. No production remote authentication, facade wiring, admission pipeline, requirement status change or support claim.

- Internal registered-test registry for admission (DEV-584). `internal/registry` maps an exact `(test_id, test_version)` to its task codec, registered baseline risk, a proxy-compatibility rule and NET-05 composite or step eligibility. It is immutable after construction, bounded to 256 entries and safe for concurrent reads. Lookup has no version fallback or partial match, and construction rejects incomplete, duplicate or codec-inconsistent entries atomically. The dependency check now restricts registry imports and forbids measurement packages from importing it; the architecture now states that validation cannot import the registry. Only test-scoped synthetic entries exist. No production entry, runner composition, admission behavior, requirement status or support claim is added.

### Fixed

- Common candidate validation now rejects duplicate, excessive or invalid UTF-8 labels and normalizes a copied label slice consistently with decoded tasks. Network Context rejects non-ASCII country/region spellings before case conversion can map them onto reviewed ASCII codes. Zero-value result decoders now reject with a binding error before processing input or producer records.

No release tag or implementation-support claim is created by these unreleased entries.
